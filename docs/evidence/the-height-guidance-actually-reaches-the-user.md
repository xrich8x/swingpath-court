# The height guidance actually reaches the user (run.py check + Court Setup tab)

> Evidence for the `the-height-guidance-actually-reaches-the-user` row in [docs/STATE.md](../STATE.md) (What has worked).
> Text preserved verbatim from SCOREBOARD.md at the 2026-08-26 split.

**The measurement existed for a week and shipped to nobody.** `calibration.expected_call_accuracy` and `CALL_MAJORITY_FLOOR_PCT` were computed, documented and pinned by 6 tests — and reachable only through `courtfit.setup_verdict`, which was called by exactly two files, both of them TOOLS (`court_setup_server.py`, `audit_new_clips.py`). `run.py check`, the command named *"pre-flight: grade your court framing"*, never called it; it ended at `elevation 2.68`, an unbounded proxy. The dashboard did not show it either. Now both do: check prints *"~58% of close calls correct / floor is 56%"* and shouts **THIS MOUNT ADDS NOTHING** at or below the floor, **each with the sentence saying what it was measured against** (rule 2 — it is a curve over camera HEIGHT from simulated flights, not a measurement of the user's clip, and it first shipped without that line); the Court Setup tab grades the mount live as you drag corners (green/amber/red), off the camera height `fitCamToQuad` already solves for the shape lock, so it costs no extra fitting. **`check` also stopped being a second opinion**: it used to read ONE frame through `detect_court_learned` -> `detect_court` while `analyze` runs `courtfit` consensus over 8 and accepts only >=6 — measured on demo30 with no keypoints, the old path returned a court and graded it POOR while analyze **REFUSES the clip** ("2 of 8 frames (needs 6)"). It now calls `pipeline.calibrate_video`, the same entry point, so the two cannot drift (trap T15). `--court-weights` removed from check: analyze has no such flag, and an override only check honoured would rebuild the divergence. JS mirror verified **EXACT against Python on 17 heights**. 8 tests, 373 total | 2026-08-14
